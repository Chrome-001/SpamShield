# SpamShield model card

## Model details
- **Name:** SpamShield text classifier v1.0.0
- **Type:** TF-IDF vectorizer (word unigrams + bigrams, English stop words,
  `max_features=5000`) + Logistic Regression (`max_iter=1000`, seed 42).
- **Baseline:** Multinomial Naive Bayes trained with the same vectorizer
  (`train.py --compare` writes `reports/model_comparison.json`).
- **Task:** binary message classification (`ham` vs `spam`); optional 3-class
  (`ham`/`spam`/`scam`) supported only when the dataset carries separately
  verified `scam` labels — spam is never silently relabeled as scam.
- **Training:** CPU-only, scikit-learn Pipeline, stratified train/test split
  (seed 42) when each class has ≥ 2 samples.

## Intended use (educational)
Helps users recognize suspicious-message patterns. **Not** a production
security product: do not use to block messages, accuse senders, or make
safety-critical decisions.

## Training data
- **Bundled:** `data/sample_messages.csv` — 45 hand-written synthetic messages
  (25 ham / 20 spam). Illustrative only; not representative of real traffic.
- **Recommended real data:** SMS Spam Collection (Almeida & Hidalgo, 2011, UCI
  ML Repository), ~5,574 messages. Must be downloaded manually; respect its
  license and cite it. See `data/README.md`.

## Evaluation
- Metrics come **only** from the held-out test split; see
  `reports/evaluation.json` and `reports/confusion_matrix.png` (regenerated by
  `train.py`, never hand-edited).
- Report accuracy **plus** macro/weighted precision, recall, F1 and per-class
  metrics — accuracy alone is misleading under class imbalance (a majority-class
  baseline can look "accurate" while missing most spam).
- Error analysis lists false positives/negatives in `evaluation.json`.

## Limitations & biases
- Tiny synthetic training set → narrow vocabulary, unreliable on novel phrasing.
- English-only, short-text tuned; code-switching (e.g. Taglish) and new scam
  lures degrade performance.
- Probabilities are model scores, **not** calibrated real-world fraud chances.
- Rule-based indicators are heuristics, not verdicts.
- No scam-labeled training data bundled → no validated scam-detection claims.

## Privacy & ethics
- Local-only inference; no uploads, no telemetry, no persistent message store.
- Logs must never contain message contents.
- joblib files are pickle-based: load only files you trained or trust.

## Reproducibility
`python train.py --data data/sample_messages.csv` (seed 42) regenerates
`models/` + `reports/` artifacts. Environment: Python 3.11+, pinned deps in
`requirements.txt`. Low-memory tip: reduce `--max-features` (e.g. 2000).
Verified: two consecutive training runs produce identical metrics
(only `trained_at` timestamps and timing noise differ).
